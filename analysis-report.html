1. Project Overview

Backend

Python 3.13 real-time pipeline engine. FastAPI + uvicorn serving a graph of threaded audio/video/AI nodes connected via pub/sub channels.

Python 3.13 FastAPI PyTorch litellm websockets

Frontend

React 19 + TypeScript graph editor using @xyflow/react. Source of truth for pipeline topology, synced to backend via REST.

React 19 TypeScript 5.9 Vite 7 Tailwind CSS @xyflow/react

Desktop

Tauri 2 (Rust) desktop wrapper. Bundles frontend dist, proxies to backend. Supports file dialogs and shell integration.

Tauri 2.10 Rust 1.77 serde

Pipeline Architecture

Nodes are threaded components (Sources, Conduits, Sinks) connected by Channels. GraphManager dynamically creates/destroys nodes to match the frontend graph state.

2. Critical Bugs

4 issues

AsyncIO Event Reuse Race Condition

Critical
backend/src/core/graph.py:362-364

The asyncio.Event is reassigned immediately after .set():

self._ui_version += 1
self._ui_changed.set()
self._ui_changed = asyncio.Event()   # new event; old waiters orphaned

Any coroutine already awaiting the old event object may never wake up because it holds a reference to the discarded event. New waiters see a fresh, unset event and block correctly — but the transition window is a race.

Impact: UI WebSocket listeners can miss channel updates or hang indefinitely, requiring a page refresh to recover.

WebSocket Resource Leak in STS Node

Critical
backend/src/core/conduit/sts.py:49-107

The STS node spawns daemon threads (_send_loop, interrupt listener) that access the WebSocket. If an exception occurs in run() after the WebSocket opens, these threads are not signaled to stop. The stop() method closes the WebSocket without synchronization, so a background thread can call ws.send() on an already-closed connection.

Additionally, the ReceiverIterator used by _send_loop is never explicitly closed, leaving its cursor registered in the channel indefinitely.

Impact: Resource leaks (sockets, channel cursors), potential exceptions in background threads on every pipeline stop/restart cycle.

GraphManager stop() Doesn't Await Threads

Critical
backend/src/core/graph.py:375-378

stop() iterates components and calls comp.stop(), which sets each component's _stop_event. However, it never joins the component threads:

def stop(self) -> None:
    for comp in self._components.values():
        comp.stop()    # sets event, but thread may run for seconds more

Subsequent calls to run() or graph reconfiguration can begin while old threads are still executing, causing shared-state corruption.

Impact: Data races on graph reconfiguration. Threads from the old graph may write to channels that the new graph is reading, producing garbled output or crashes.

Hardcoded WebSocket URL in Frontend

Critical
frontend/src/hooks/useUIChannel.ts:26

The UI channel WebSocket connects to a hardcoded address:

const url = `ws://localhost:8000/ui/ws`;

This breaks in any non-localhost deployment (Docker, LAN, production). Should derive the URL from window.location or an environment variable.

Impact: UI channels are completely non-functional outside local development.

3. High-Severity Issues

7 issues

Thread Cleanup Race in TTS / ASR

High
backend/src/core/conduit/tts.py:121-161 • asr.py:143-161
Worker threads are joined with a 1-second timeout. The ASR transcription API has a 60-second timeout, so the join almost always expires. The abandoned daemon thread continues holding HTTP connections, temp files, and channel cursors.
Impact: Orphaned threads accumulate on every pipeline restart, gradually exhausting connections and file descriptors.

VAD Lock Held During Model Inference

High
backend/src/core/conduit/vad.py:91-140
_check_smart_turn() runs ONNX model inference while holding self._lock. The monitor thread and the main audio processing thread both need this lock. If inference takes >100ms, the main thread blocks, and incoming audio frames queue up unboundedly.
Impact: Audio frame backlog causes latency spikes and potential memory pressure during speech pauses.

VAD Monitor Thread Not Awaited

High
backend/src/core/conduit/vad.py:262-265
The monitor thread is started as a daemon with no join. On component stop, the main run() returns while the monitor thread may still be calling _finalize_segment(), writing to output channels that are being torn down.
Impact: Corrupted segment output or exceptions writing to closed channels during shutdown.

UI Receiver Sub-ID Collision Risk

High
backend/src/api/ui/controller.py:90
sub_id = id(object()) creates a temporary object and takes its id(). The object is immediately GC-eligible, so Python can reuse the same memory address (and thus the same ID) for the next allocation. Two concurrent UI subscribers could collide on the same cursor position.
Impact: Channel cursor collisions cause frame skips or duplicate delivery to WebSocket listeners.

Channel GC Race on Cursor Values

High
backend/src/core/channel.py:69-75
_gc() computes min(self._cursors.values()) and deletes items from the front of the list. While protected by the condition lock, the design is fragile — if a new subscriber registers with latest=True and gets an offset that's about to be dropped, it will read stale or missing data.
Impact: Subscribers registered during GC may receive corrupted frame sequences.

LLM Stream Not Interruptible on Stop

High
backend/src/core/conduit/llm.py:137
The for chunk in stream: loop blocks on the LLM API with no per-iteration check of stop_event. The only way out is for the API to finish or timeout. For long generations, stop() can take 30+ seconds to take effect. No EOS frame is sent on exception, so downstream nodes hang.
Impact: Pipeline cannot be stopped promptly when an LLM call is in-flight. Downstream TTS/Speaker nodes hang waiting for EOS.

WebSocket Reconnection Stacking (Frontend)

High
frontend/src/hooks/useUIChannel.ts:35-39
The onclose handler calls setTimeout(connect, 1000) without tracking pending timeouts. If the socket disconnects and reconnects multiple times in quick succession, each close event schedules a new connect(), leading to multiple parallel WebSocket connections.
Impact: Connection storms after network instability; duplicate message delivery; memory leaks from abandoned socket objects.

4. Medium-Severity Issues

11 issues

ASR Temp File Leak on Exception

Medium
backend/src/core/conduit/asr.py:91-128
If _prepare_audio_for_transcription() throws, the outer except catches it, but the inner finally that calls os.unlink(wav_path) is never reached. Repeated API failures accumulate temp files in /tmp.

TTS StreamFilter Race on Interrupt

Medium
backend/src/core/conduit/tts.py:46, 139
The interrupt handler reassigns self._stream_filter = StreamFilter() from a separate thread while the main thread may be mid-feed() on the old instance. The assignment is not atomic relative to the processing loop, causing potentially malformed text output.

ASR Queue Not Drained on Stop

Medium
backend/src/core/conduit/asr.py:150-157
The finally block in run() is empty. Pending audio frames in _task_queue are silently discarded, and the worker thread receives no completion signal. The queue can also grow unbounded if frames arrive faster than transcription.

TTS Generation Counter Race

Medium
backend/src/core/conduit/tts.py:155-158
The lock is released before queue.put(). The interrupt handler can increment _generation in the gap between reading the generation number and enqueuing the task, causing the worker to skip valid audio.

CompositeComponent Has No Thread Safety

Medium
backend/src/core/component.py:408-434
start() and stop() have no synchronization. Concurrent calls can corrupt _inner_manager. If start() calls _inner_manager.run() while stop() sets it to None, a NoneType error occurs.

Missing Error Handling in update_node_init_args

Medium
backend/src/core/graph.py:104-128
If cls.from_args(init_args) raises, the graph is left in an inconsistent state: the old component was stopped and removed, but the new one wasn't created. No rollback logic exists.

Ungroup Operation Can Corrupt Graph

Medium
backend/src/api/graph/node/service.py:201-210
No try-except around cls.from_args() during ungroup. If any inner component fails to initialize, the graph is partially modified with some components deleted and others not yet created.

VideoSource Doesn't Handle cv2 Exceptions

Medium
backend/src/core/source/video_source.py:89-107
cap.read() can raise cv2.error if the camera disconnects mid-stream. The exception propagates uncaught, killing the component thread with no recovery or user notification.

OscFace Expression Worker Silent Death

Medium
backend/src/core/sink/osc_face.py:700-730
The _expression_worker() loop has no try-except. If the LLM call throws, the worker thread dies silently. The main run loop never learns the worker is dead, and expressions stop updating permanently.

YOLO Tracker Temp File Never Deleted

Medium
backend/src/core/conduit/yolo/object_segmenter.py:92-100
NamedTemporaryFile(delete=False) creates a YAML file that is saved to self._tracker_yaml but never cleaned up in any destructor or finally block. Each component instantiation leaks one file.

Frontend Project Polling Race

Medium
frontend/src/App.tsx:815-847
The polling loop uses a cancelled flag but doesn't abort in-flight fetchCurrentProject() promises. On rapid unmount/remount, stale promises resolve and update state on an unmounted component.

High

8. Recommendations

Immediate (Safety & Correctness)

  • 1. Fix GraphManager.stop() to join component threads with reasonable timeouts before returning.
  • 2. Add try-except in all worker threads (TTS, ASR, VAD monitor, OscFace expression worker) to prevent silent death.
  • 3. Replace the asyncio Event reuse pattern in graph.py with a version-checked loop or asyncio.Condition.
  • 4. Make the frontend WebSocket URL derive from window.location instead of hardcoding localhost.

Short-Term (Stability)

  • 5. Add bounded queues with backpressure to ASR and TTS to prevent unbounded memory growth.
  • 6. Ensure all ReceiverIterator usages have explicit cleanup (close/unregister) in finally blocks.
  • 7. Replace print() with Python logging module throughout the backend for structured, level-controlled output.
  • 8. Add pytest to the backend and vitest to the frontend with at least core pipeline and component tests.

Medium-Term (Architecture)

  • 9. Implement a unified component lifecycle manager with ordered startup/shutdown and thread join guarantees.
  • 10. Switch from daemon threads to explicitly managed threads so shutdown is deterministic.
  • 11. Add Docker support for reproducible builds and deployments.
  • 12. Expand CI/CD to include test runs, build verification, coverage gates, and staging deploy.
